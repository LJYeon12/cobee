# Cobee 제품 요구사항 정의서

[문서 목차](README.md)

## 1 서비스 개요

Cobee는 룸메이트를 모집하고, 회원에게 맞는 모집글을 추천하는 서비스이다.
회원은 본인의 생활 특성과 원하는 상대 조건을 등록한다.
모집글을 탐색하고, 관심 있는 글에 질문하거나 지원한다.
모집자는 지원자를 확인하고 수락 또는 거절한다.

## 2 사용자

| 사용자 | 주요 활동 |
|--------|-----------|
| 회원 | 본인 정보, 공개 프로필, 상대방 선호 조건 관리 |
| 지원자 | 모집글 탐색, 추천 조회, 북마크, 질문, 지원, 지원 결과 확인 |
| 모집자 | 모집글 관리, 지원자 조회, 지원 수락·거절 |

한 회원은 지원자와 모집자로 활동할 수 있다.

## 3 기능 요구사항

### FR-01 네이버 로그인

- 사용자는 네이버 계정으로 로그인할 수 있다.
- 네이버 사용자 식별자로 회원을 구분한다.
- 첫 로그인 시 회원 정보를 등록한다.
- 다시 로그인하면 이름과 프로필 이미지를 갱신한다.
- 로그인 성공 시 Access Token과 Refresh Token을 발급한다.
- 탈퇴 처리 중인 회원은 로그인을 완료할 수 없다. 로그인 완료 전에 모집 서비스와 Redis의 쓰기 상태를 초기화한다.

### FR-02 토큰 재발급과 로그아웃

- 회원은 Refresh Token으로 새 Access Token과 Refresh Token을 발급받을 수 있다.
- 재발급 요청의 토큰은 유효해야 하며, 저장된 토큰과 일치해야 한다.
- 재발급 시 저장된 Refresh Token을 새 토큰으로 교체한다.
- 로그아웃 시 저장된 Refresh Token을 삭제한다.
- 탈퇴 처리 중인 회원의 토큰 재발급은 거부한다.

### FR-02-1 회원 탈퇴

- 탈퇴 요청은 202와 작업 ID를 반환한다. 접수와 완료를 구분한다.
- 회원은 본인의 탈퇴 처리 상태를 조회할 수 있다. 반복 요청은 같은 작업을 반환한다.
- 쓰기 차단 전에 커밋한 모집 데이터는 탈퇴 정리에 포함한다. 차단 뒤에는 진행 중이던 요청도 저장하지 못한다.
- 중간 실패는 기록한 단계부터 다시 처리한다. 모집 데이터 정리와 회원 삭제가 끝난 뒤 완료로 표시한다.
- 처리 범위와 클라이언트 변경은 [회원 탈퇴 운영 절차](withdrawal.md)를 따른다.

### FR-03 회원 정보와 공개 프로필

- 회원은 본인 정보를 조회할 수 있다.
- 회원은 본인 프로필 이미지를 변경할 수 있다.
- 회원은 공개 프로필을 등록, 조회, 수정, 삭제할 수 있다.
- 회원은 공개 프로필 ID로 상대방의 프로필을 조회할 수 있다.
- 회원별 공개 프로필은 한 개로 관리한다.
- 공개 프로필을 등록하면 가입 완료 상태로 변경한다.

| 공개 프로필 항목 | 내용 |
|------------------|------|
| 생활 패턴 | 아침형, 저녁형 |
| 성격 | 내향형, 외향형 |
| 흡연 | 본인 흡연 여부 |
| 코골이 | 본인 코골이 여부 |
| 반려동물 | 본인 반려동물 보유 여부 |
| 자기소개 | 본인을 소개하는 글 |

### FR-04 신분증 OCR 확인

- 회원은 신분증 이미지를 제출해 본인 정보를 확인할 수 있다.
- 신분증에서 이름, 성별, 생년월일을 읽는다.
- 이름과 회원 정보가 일치하는지 확인한다.
- 등록된 성별과 생년월일이 있으면 신분증 정보와 비교한다.
- 성별이나 생년월일이 비어 있으면 신분증 정보로 채운다.
- 확인에 성공하면 회원의 OCR 확인 상태를 변경한다.

### FR-05 상대방 선호 조건

- 회원은 상대방 선호 조건을 등록, 조회, 수정, 삭제할 수 있다.
- 회원별 선호 조건은 한 개로 관리한다.
- 본인 생활 특성과 상대방에게 원하는 조건을 구분한다.

| 선호 항목 | 내용 |
|-----------|------|
| 성별 | 남성, 여성, 상관없음 |
| 생활 패턴 | 아침형, 저녁형 |
| 성격 | 내향형, 외향형 |
| 흡연 수용 | 흡연하는 상대를 수용하는지 여부 |
| 코골이 수용 | 코골이가 있는 상대를 수용하는지 여부 |
| 반려동물 수용 | 상대의 반려동물을 수용하는지 여부 |
| 동거 인원 | 2~10명 |
| 선호 나이 | 최소 나이와 최대 나이 |

### FR-06 모집글과 이미지 등록

- 모집자는 모집글을 등록할 수 있다.
- 등록한 모집글의 상태는 `RECRUITING`이다.
- 주소를 좌표로 변환해 주소, 위도, 경도를 저장한다.
- 모집글 등록 시 이미지를 함께 올릴 수 있다.
- 모집자는 본인 모집글에 이미지를 추가할 수 있다.
- 이미지 URL과 표시 순서를 저장한다.

| 모집글 항목 | 내용 |
|-------------|------|
| 제목 | 모집글 제목 |
| 모집 인원 | 모집할 사람 수 |
| 보증금 | 최소 금액과 최대 금액 |
| 월세 | 최소 금액과 최대 금액 |
| 선호 나이 | 최소 나이와 최대 나이 |
| 선호 성별 | 남성, 여성, 상관없음 |
| 생활 조건 | 생활 패턴, 성격, 흡연, 코골이, 반려동물 |
| 방 보유 여부 | 방이 있는지 여부 |
| 주소 | 주거 위치 |
| 상세 설명 | 모집과 주거에 관한 설명 |
| 추가 설명 | 추가 안내 내용 |

| 이미지 입력 조건 | 값 |
|------------------|----|
| 한 번에 올리는 수 | 최대 3개 |
| 파일 크기 | 파일당 최대 5 MiB |
| 파일 형식 | JPEG, JPG, PNG, WebP |

프로필 이미지에도 같은 파일 크기와 형식 조건을 적용한다.

### FR-07 모집글 조회와 관리

- 회원은 모집글 목록과 상세 정보를 조회할 수 있다.
- 모집자는 본인이 작성한 모집글 목록을 조회할 수 있다.
- 모집자는 모집글의 등록 내용을 수정할 수 있다.
- 주소를 수정하면 주소와 좌표를 함께 갱신한다.
- 모집자는 모집글을 삭제할 수 있다.

### FR-08 위치와 비용 필터

회원은 다음 조건으로 모집글을 조회할 수 있다.

| 필터 | 조회 조건 |
|------|-----------|
| 위치 | 위도·경도를 중심으로 입력한 반경 안의 글 |
| 모집 인원 | 글의 모집 인원이 입력값 이하인 글 |
| 보증금 | 글의 최소·최대 보증금이 입력 범위 안에 있는 글 |
| 월세 | 글의 최소·최대 월세가 입력 범위 안에 있는 글 |

- 위치 필터는 위도, 경도, 반경을 함께 입력한다.
- 반경 단위는 km이다.
- 각 조건은 선택해서 사용할 수 있다.

### FR-09 북마크

- 회원은 관심 있는 모집글을 북마크할 수 있다.
- 같은 글을 중복으로 북마크할 수 없다.
- 본인이 작성한 글은 북마크할 수 없다.
- 북마크 목록은 저장한 시각의 내림차순으로 조회한다.
- 회원은 본인의 북마크를 개별 또는 전체 해제할 수 있다.

### FR-10 댓글과 답글

- 회원은 모집글에 댓글을 작성할 수 있다.
- 기존 댓글을 지정해 답글을 작성할 수 있다.
- 댓글에는 본문과 비공개 여부를 입력한다.
- 모집글별로 댓글과 답글을 조회할 수 있다.
- 댓글 응답에는 댓글 ID, 글 ID, 부모 댓글 ID, 작성자 이름, 프로필 이미지, 본문, 비공개 여부를 제공한다.

### FR-11 모집글 지원

- 회원은 모집글에 지원할 수 있다.
- 같은 회원의 같은 글에 대한 중복 지원을 막는다.
- 지원 기록에 지원자, 모집글, 지원일, 지원 상태를 저장한다.
- 새 지원의 상태는 `ON_WAIT`이다.
- 회원은 본인이 지원한 모집글을 조회할 수 있다.
- 지원 상태별로 본인의 지원 내역을 조회할 수 있다.
- 특정 모집글에 본인이 지원했는지 확인할 수 있다.

### FR-12 지원자 조회와 수락·거절

- 모집자는 모집글의 지원자 목록을 조회할 수 있다.
- 지원 상태별로 지원자를 조회할 수 있다.
- 모집자는 지원을 수락하거나 거절할 수 있다.
- 수락한 지원은 `MATCHING`으로 변경한다.
- 거절한 지원은 `REJECTED`로 변경한다.
- 지원자는 본인 지원 내역에서 결과를 확인할 수 있다.

### FR-13 활동 알림

- 회원은 푸시 알림을 받을 기기 토큰을 등록할 수 있다.
- 알림에는 발생 원인, 발신자, 수신자, 제목, 본문을 저장한다.
- 수신자를 지정해 푸시 알림을 발송한다.
- 댓글과 답글의 작성자에게 본인 활동 알림을 보내지 않는다.

| 발생 사건 | 알림 수신자 |
|-----------|-------------|
| 새 지원 | 모집글 작성자 |
| 지원 수락·거절 | 지원자 |
| 새 댓글 | 모집글 작성자 |
| 답글 | 부모 댓글 작성자 |

### FR-14 개인화 모집글 추천

- 회원 ID를 기준으로 모집글을 추천한다.
- 요청한 개수에 맞춰 추천 결과를 반환한다.
- 추천 결과에 모집글 정보, 순위, 점수, 추천 이유를 제공한다.
- 추천 이유의 포함 여부를 선택할 수 있다.
- 추천 방식과 가중치에 따라 결과를 정렬한다.
- 추천 결과가 없으면 빈 목록을 반환한다.
- 학습 모델을 불러올 수 없으면 규칙 추천을 사용한다.

| 요청 항목 | 조건 |
|-----------|------|
| 회원 ID | 양의 정수 |
| 추천 개수 | 1~100개, 기본 10개 |
| 추천 이유 포함 | 기본값 `true` |

| 응답 항목 | 내용 |
|-----------|------|
| 모집글 정보 | 글 ID, 작성자 ID, 모집 조건, 비용, 위치, 모집 상태 |
| 순위 | 1부터 시작하는 추천 순서 |
| 점수 | 0~1 범위의 추천 점수 |
| 추천 이유 | 일치 항목, 점수의 백분율, 상세 점수 정보 |
| Phase | 추천 방식의 단계 |
| 모델 구분 | Phase와 추천 비중을 나타내는 값 |
| 생성 시각 | 추천 결과를 만든 시각 |

### FR-15 회원 탈퇴

- 회원은 계정을 탈퇴할 수 있다.
- 탈퇴 시 회원이 작성한 모집글과 지원 기록을 삭제한다.
- 회원 정보, 공개 프로필, 선호 조건을 삭제한다.
- 저장된 Refresh Token을 삭제한다.

## 4 추천 정책

### 4.1 규칙 추천의 후보 조건

- 모집 중인 글을 대상으로 한다.
- 본인이 작성한 글을 제외한다.
- 이미 지원한 글을 제외한다.
- 이미 북마크한 글을 제외한다.
- 작성자 정보가 있는 글을 대상으로 한다.

### 4.2 특성 비교와 점수

회원의 선호 조건과 모집글 작성자의 특성을 비교한다.
가중치를 적용한 거리로 유사도를 계산한다. 거리가 가까운 글을 먼저 추천한다.

| 비교 항목 | 비교 내용 | 가중치 |
|-----------|-----------|--------|
| 성별 | 회원의 선호 성별과 작성자의 성별 | 5 |
| 나이 | 회원과 작성자의 실제 나이 | 3 |
| 생활 패턴 | 회원의 선호 패턴과 작성자의 패턴 | 1 |
| 성격 | 회원의 선호 성격과 작성자의 성격 | 1 |
| 흡연 | 회원의 수용 여부와 작성자의 흡연 여부 | 1 |
| 코골이 | 회원의 수용 여부와 작성자의 코골이 여부 | 1 |
| 반려동물 | 회원의 수용 여부와 작성자의 반려동물 보유 여부 | 1 |
| 인원 | 회원의 동거 인원과 글의 모집 인원 | 1 |

성별과 나이는 유사도 점수에 반영한다.
추천 이유에는 성별 선호 일치, 선호 나이 범위의 겹침, 생활 패턴, 성격, 생활 습관의 수용 여부를 표시한다.

### 4.3 Phase별 추천 비중

상호작용 수는 전체 지원 기록 수와 북마크 수를 합쳐 계산한다.
상호작용 수에 따라 규칙 추천과 활동 기록 기반 추천의 비중을 정한다.

| Phase | 상호작용 수 | 규칙 추천 | 활동 기록 기반 추천 |
|-------|-------------|-----------|----------------------|
| P1 | 0~99 | 100% | 0% |
| P2 | 100~999 | 60% | 40% |
| P3 | 1,000 이상 | 20% | 80% |

활동 기록 기반 추천에는 SVD 모델을 사용한다.
두 방식의 점수를 각각 0~1로 변환한 뒤 가중 평균으로 혼합한다.
같은 값만 있는 점수 집합은 각 점수를 0.5로 변환한다.

### 4.4 학습 점수

| 활동 | 학습 점수 |
|------|-----------|
| 지원 대기 `ON_WAIT` | 3 |
| 지원 수락 `MATCHING` | 4 |
| 지원 거절 `REJECTED` | 1 |
| 최종 매칭 `MATCHED` | 5 |
| 북마크 | 4 |

같은 회원과 모집글에 여러 활동 기록이 있으면 마지막 시각의 기록을 사용한다.

## 5 상태 정의

### 5.1 회원 상태

| 항목 | 값 | 의미 |
|------|----|------|
| 가입 완료 | `isCompleted=false` | 공개 프로필 등록 전 |
| 가입 완료 | `isCompleted=true` | 공개 프로필 등록 완료 |
| OCR 확인 | `ocrValidation=false` | 신분증 확인 전 |
| OCR 확인 | `ocrValidation=true` | 신분증 확인 완료 |

### 5.2 모집 상태

| 상태 | 의미 |
|------|------|
| `RECRUITING` | 모집 중 |
| `RECRUIT_OVER` | 모집 종료 |

### 5.3 지원 상태

| 상태 | 의미 |
|------|------|
| `ON_WAIT` | 지원 후 대기 |
| `MATCHING` | 지원 수락 |
| `REJECTED` | 지원 거절 |
| `MATCHED` | 최종 매칭 |

## 6 추천 데이터 처리

### 6.1 데이터 동기화

- 회원, 모집글, 지원 기록, 북마크, 댓글 데이터를 조회한다.
- 마지막 동기화 시각이 없으면 전체 데이터를 조회한다.
- 마지막 동기화 시각이 있으면 이후 수정된 데이터를 조회한다.
- 회원, 모집글, 지원 기록, 북마크를 추천용 저장소에 반영한다.
- 동기화할 데이터가 있으면 저장 후 모델 학습을 수행한다.
- 동기화 완료 시 마지막 동기화 시각을 저장한다.

### 6.2 자동 처리

| 작업 | 주기 |
|------|------|
| 데이터 동기화 | 1시간 간격 |
| 상호작용 집계와 Phase 갱신 | 매일 04:50 |

- 데이터 동기화와 Phase 갱신을 수동으로 실행할 수 있다.
- 예약 작업 목록과 다음 실행 시각을 조회할 수 있다.

### 6.3 추천 정보 조회

- 추천 서비스와 DB 연결 상태를 조회할 수 있다.
- 적용된 Phase, 상호작용 수, 추천 비중을 조회할 수 있다.
- 학습 모델 파일의 사용 가능 여부를 조회할 수 있다.
- 회원 수, 전체 모집글 수, 모집 중인 글 수를 조회할 수 있다.
- 북마크 수, 지원 수, 전체 상호작용 수를 조회할 수 있다.
