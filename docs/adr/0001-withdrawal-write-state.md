# 회원 탈퇴의 최종 쓰기 판정을 각 서비스 DB에 둔다

2026-10-31. 상태: accepted.

회원 서비스의 조회 응답은 모집 데이터의 저장 시점까지 회원 상태를 보장하지 않는다. 모집 DB의 회원별 상태 행을 쓰기와 같은 트랜잭션에서 잠그고, 탈퇴도 같은 행의 잠금을 얻어 차단하도록 결정했다. 이 방식은 서버 인스턴스 수와 관계없이 이미 진행 중인 쓰기의 순서를 정한다.

Redis 분산락은 락의 유효 기간과 PostgreSQL 커밋 사이를 별도로 다뤄야 한다. 필요한 최종 검증을 데이터가 저장되는 DB에 모았다. Redis는 요청 입구 차단과 자격 증명 철회를 담당한다. 차단 상태 확인과 Refresh Token 저장도 Redis 안에서 함께 실행해 늦은 재발급이 철회를 되돌리지 못하게 했다.

차단 행은 회원 삭제 뒤에도 유지하며, 지연된 등록이 ACTIVE로 되돌리지 못하게 한다. 삭제는 복원 보상보다 완료까지 이어가는 방식을 선택했다. 회원 DB의 작업 기록, 반복 가능한 내부 호출, 만료된 처리권의 회수로 진행한다.

같은 회원과 관련 회원의 쓰기는 잠금을 기다릴 수 있다. 외부 I/O를 쓰기 트랜잭션에서 분리하고, 트랜잭션 시간을 제한하며 비용을 관측한다. 이 결정의 검증과 적용 범위는 [탈퇴 운영 절차](../withdrawal.md)와 [TDD 기록](../../diagnostics/2026-10-31/withdrawal-tdd/README.md)에 있다.
